# Substrate pallet weight mis-declaration — detect, PoC, score

Verified end-to-end on Deeper Chain (`deeper-chain`, Rust/FRAME, **spec_version 76** live
on `wss://mainnet-deeper-chain.deeper.network`, 2026-10-28). PoC passing, scored Medium.

## Why this class exists

`weights.rs` is **autogenerated** and benchmarked against a small `dev` state. Any code
path that iterates a **user-growable** storage map is benchmarked near N≈3 but declared
near-constant, while on mainnet it is O(N). The declaration and the code disagree — that
is the bug. It is provable by reading two files, which makes it cheap to confirm and
cheap for the vendor to verify.

Header of a generated weights file tells you the benchmark was tiny:

```
//! THIS FILE WAS AUTO-GENERATED USING THE SUBSTRATE BENCHMARK CLI VERSION 4.0.0-dev
//! DATE: 2023-11-06, STEPS: `5`, REPEAT: `1`, ...
//! WORST CASE MAP SIZE: `1000000`
//! CHAIN: `Some("dev")`
```

`STEPS: 5` / `REPEAT: 1` means the curve was fit from almost nothing.

## Step 1 — three reads, then a diff

```python
# a. every unbounded iteration in the pallets
re.finditer(r"([A-Za-z_][A-Za-z0-9_]*)::<T>::(iter|iter_keys|iter_values)\s*\(", src)

# b. the storage decl — capped or not?
re.search(r"pub type (\w+)<T: Config> =[\s\S]{0,200}?;", src)
#    StorageMap<_, Twox64Concat, .., ValueQuery>   == uncapped
#    BoundedVec / CountedStorageMap                == capped -> drop the lead

# c. what weights.rs claims
re.search(r"fn <extrinsic>\(\)\s*->\s*Weight\s*\{[\s\S]{0,300}?\}", weights_rs)
```

The decisive question: **can a signed account add entries to that map?** If yes, N is
attacker-influenced and a constant declaration is wrong. If the map is only written under
`ensure_root`, it is not a finding.

Deeper Chain answer:

## Step 2 — the tell that makes it undeniable: one site caps, the sibling does not

```rust
// elect() — iterates AND truncates
// L2921
let mut validators: Vec<(T::AccountId, u32, EraIndex)> = Validators::<T>::iter()
// L2950
validators.truncate(Self::validator_count() as usize);

// delegate_any() — iterates the same map, never truncates
// L2394
fn delegate_any(delegator: T::AccountId) -> DispatchResult {
    let validators: Vec<_> = Validators::<T>::iter_keys().collect();
```

Measured in the mock: `validator_count() cap = 2` while `delegate_any` iterated all 503
entries present. Put **both** sites in the report — this is the substrate form of
web3-audit's "read ALL sibling functions" rule, and it converts "maybe intended" into
"clearly an omission".

## Step 6 — the five harness traps (all were MINE, not the target)

| Trap | Symptom | Fix |
|---|---|---|
| **CRLF checkout** | `include_str!("lib.rs")` compared against `"\n"` never matches | `.replace('\r', "")` before matching |
| **`ExtBuilder` vs `new_test_ext()`** | `error[E0433]: use of undeclared type ExtBuilder` | differ per pallet — read `tests.rs` imports first (`staking`=ExtBuilder, `deeper-node`=new_test_ext) |
| **empty mock account** | `assert_eq!(after - before, amount)` fails with `0` | scan `1..300` for an account with `free_balance > 0` in that mock |
| **weight generics** | `type annotations needed` on `BlockWeights::get()` | `<... as Get<BlockWeights>>::get()` fully qualified |
| **two name filters** | `error: unexpected argument 'd01c' found` | `cargo test` takes ONE filter — use a shared prefix (`d01`) |

Put these in the report appendix. A reviewer re-running the PoC hits every one.

## Step 7 — the false negative that nearly killed the whole finding

`re.split(r"#\[cfg\(test\)\]", src)` **truncates a pallet at its HEADER**, because FRAME
declares test modules at the top of the file:

```rust
#[cfg(test)]
mod mock;
#[cfg(test)]
mod tests;
```

Splitting on the first occurrence returned **903 bytes** for a **138 KB** file containing
39 extrinsics *and* the O(N) bug. Every subsequent grep reported zero hits, and the run
looked like a clean negative.

```python
# take the LAST occurrence (the real tests module at EOF)
m = list(re.finditer(r"#\[cfg\(test\)\]", src))
body = src[:m[-1].start()] if m else src

# gate: a big mismatch means truncation, not a small file
assert len(body) > 0.5 * os.path.getsize(path), "truncated at header, re-read the file"
```

Second silent-negative path: a shell `grep -rn "for .* in .*::<.*>::iter"` under MSYS bash
returned nothing and read as "no unbounded loops". Use Python `re` for these patterns.

## Step 8 — severity: reachability decides the tier

The gap is real; the tier is not automatic. Answer all three:

1. **Trigger authority.** `staking_delegate` requires
   `verify_atomos_signature(nonce, signature, who)` over
   `blake2_256(atomos_accountid ++ nonce ++ sender)`, and `AtmosAccountid` is a single
   global `StorageValue` (not per-device). An internet-only attacker cannot submit it.
2. **Repeatability.** Gate `ensure!(dst_level > cur_level)` with
   `CreditLevel = Zero..Eight` (9 variants) caps one account at **8** triggers — no loop.
3. **Already-paid cost.** `elect()` walks the same set every era, so a large validator set
   is not entirely new as a cost.

Constant weight for O(N) work **with an authenticated trigger = Medium**. Reserve
High/Critical for a path an unauthenticated or self-service actor can drive. Calling it a
"remote chain halt" is the overclaim that gets the report closed.

## Adjacent: `#[transactional]` asymmetry

Deeper Chain's `staking/lib.rs` had exactly **one** `#[transactional]`, on
`usdt_staking_delegate` (index 1) but **not** on `staking_delegate` (index 0) — which moves
DPR at L3171, mutates balances, updates credit, then calls the fallible `delegate_any()`.

Whether an `Err` there persists the transfer depends on outer dispatch wrapping. Prove
that the transfer is real (`pool before = 0, after = 1, moved = 1`), report the asymmetry
as proven, and do **not** claim fund loss without a reachable `Err`. Same discipline as
web3-audit's "prove the economics before claiming theft".
