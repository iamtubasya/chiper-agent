# Substrate pallet: build, mock-runtime PoC, and the kill-list

Verified 2026-10-28 against `deeper-chain/deeper-chain` @ `ce700b14` (spec_version 76).
Every number here was **measured on this host**, not estimated.

---

## 1. Toolchain — the repo pins its own

```toml
# rust-toolchain
[toolchain]
channel = "nightly-2023-05-22"
targets = [ "wasm32-unknown-unknown" ]
```

Substrate from that era does not build on current stable or current nightly. A wrong compiler
produces hundreds of edition/trait errors that read as broken source — they are not.

```bash
rustup toolchain install nightly-2023-05-22 --profile minimal --component rust-src
rustup run nightly-2023-05-22 cargo check --offline
```

`detected conflict: 'bin\rust-analyzer.exe'` during install is harmless — drop the component
and confirm with `rustup run <tc> cargo --version`.

## 2. First build: fetch once, backgrounded

Frame/sp-* come from a **git dependency**, so `--offline` fails until fetched:

```
error: failed to get `frame-benchmarking` as a dependency
  can't checkout from 'https://github.com/paritytech/polkadot-sdk': you are in the offline mode
```

```bash
rustup run <tc> cargo fetch > fetch.log 2>&1       # ~22 min; background + notify
rustup run <tc> cargo test --offline <filter> -- --nocapture --test-threads=1
```

Cold `cargo test` on one pallet compiled **307 crates**, then 8m39s total. Foregrounding it
hits the tool timeout and a slow build gets misread as a failure. After the first build the
test binary re-runs in seconds.

## 3. Mock-runtime PoC without touching their `tests.rs`

Their `tests.rs` is often 100+ KB and conflicts on re-clone. Add a module instead:

```rust
// pallets/<name>/src/d01_poc.rs
use super::*;
use mock::*;

#[test]
fn d01_something() {
    ExtBuilder::default().build_and_execute(|| {
        Validators::<Test>::insert(account, ValidatorPrefs::default());   // seed storage directly
        // call the function under test, then assert the OBSERVED value
    });
}
```

```rust
// lib.rs, immediately after the existing `mod tests;`
#[cfg(test)]
mod d01_poc;
```

Working primitives:

| Need | Call |
|---|---|
| repo harness | `ExtBuilder::default().build_and_execute(\|\| { ... })` |
| seed storage | `<SomeMap<Test>>::insert(k, v)` |
| reproduce the suspect call | `<SomeMap<Test>>::iter_keys().collect()` |
| per-entry cost | `std::time::Instant` around the collect |
| declared weight | `<Test as Config>::WeightInfo::fn_name()` |
| block budget | `<<Test as frame_system::Config>::BlockWeights as Get<BlockWeights>>::get().max_block` |
| db weight | `<<Test as frame_system::Config>::DbWeight as Get<RuntimeDbWeight>>::get()` |
| find a funded account | scan `1..300` for `free_balance(&c) > 0`, then assert |

The `BlockWeights`/`DbWeight` type annotations are **mandatory** — bare `BlockWeights::get()`
gives `E0282: type annotations needed`.

## 4. Weight mis-declaration, end to end

**The call site** (`pallets/staking/src/lib.rs` L2385):

```rust
fn delegate_any(delegator: T::AccountId) -> DispatchResult {
    let validators: Vec<_> = Validators::<T>::iter_keys().collect();   // O(N) storage reads
    ...
}
```

**The storage** — unbounded:

```rust
pub type Validators<T: Config> =
    StorageMap<_, Twox64Concat, T::AccountId, ValidatorPrefs, ValueQuery>;
```

**Permissionless registration** (L1394) — only `ensure_signed` + `ledger()`, no bond-size or
count gate; entry costs `ExistentialDeposit = DPR/5 = 0.2 DPR`:

```rust
let controller = ensure_signed(origin)?;
let ledger = Self::ledger(&controller).ok_or(Error::<T>::NotController)?;
<Validators<T>>::insert(stash, prefs);
```

**The declaration** (`weights.rs`, autogenerated, benchmarked on a `dev` chain):

```rust
fn staking_delegate() -> Weight {
    //  Measured: `1940`   Estimated: `10355`
    Weight::from_parts(2_656_141_000, 10355)
        .saturating_add(T::DbWeight::get().reads(16_u64))     // fixed 16
        .saturating_add(T::DbWeight::get().writes(9_u64))
}
```

**The internal contrast** — same file, one site capped, one not:

```
elect()        : Validators::<T>::iter() ... validators.truncate(Self::validator_count())
delegate_any() : Validators::<T>::iter_keys().collect()
```
Measured: `validators = 503, validator_count() cap = 2` → `delegate_any() iterates all 503`.

**Measured scaling** (`d01b_scaling_curve`):

```
N=   100  iter_keys=  100  elapsed=   6.12ms  per-entry=61.15µs  real_reads=116    declared=16
N=   500  iter_keys=  500  elapsed=  32.45ms  per-entry=64.91µs  real_reads=516    declared=16
N=  1000  iter_keys= 1000  elapsed=  68.23ms  per-entry=68.23µs  real_reads=1016   declared=16
N=  2000  iter_keys= 2000  elapsed= 133.37ms  per-entry=66.69µs  real_reads=2016   declared=16
N=  5000  iter_keys= 5000  elapsed= 332.91ms  per-entry=66.58µs  real_reads=5016   declared=16
N= 10000  iter_keys=10000  elapsed= 700.86ms  per-entry=70.09µs  real_reads=10016  declared=16
```

Near-linear at ~61–70 µs/entry. At N=10,000: **10,016 reads performed, 16 charged** —
625× under-declared, 700 ms of real work.

**Budget projection** (`d01c`): `max_block ref_time = 1_000_000_000_000`,
`DbWeight.read = 25_000_000` → ~39,841 unaccounted reads exceed the whole block on one call;
with `NORMAL_DISPATCH_RATIO = 75 %` and 5 s blocks, ~10,714 entries consume the normal queue.
Capital at 0.2 DPR each ≈ 2,143 DPR, locked but recoverable via unbond.

## 5. Severity bounding — why this stayed Medium

Three reads, applied to that finding:

**5.1 Gating key is global.**
```rust
pub(super) type AtmosAccountid<T: Config> = StorageValue<_, T::AccountId>;   // SINGLE
pub(super) type TmpAtmosAccountid<T: Config> = StorageValue<_, T::AccountId>;
```
`StorageValue` = one key for the whole chain; the signed message is
`blake2_256(atomos_accountid ++ nonce ++ sender)`. An internet-only attacker cannot produce
that signature. Contrast with `StorageMap<_, _, AccountId, _>`, which would make it
per-account.

**5.2 Trigger is capped.** Gate `ensure!(dst_level > cur_level)` (L3164) and
`CreditLevel` has exactly **9 variants** `Zero..Eight` → max 8 triggers per account.

**5.3 The cost is partly already paid.** `elect()` walks the validator set every era
(truncated for its own purposes), so a large set is an accepted periodic cost.

Conclusion recorded: weight objectively wrong → **Medium**, not Critical. Write the three
bounds into the report so "can anyone actually send this?" is pre-answered.

## 6. `#[transactional]` asymmetry

```rust
#[pallet::call_index(0)]
#[pallet::weight(T::WeightInfo::staking_delegate())]
pub fn staking_delegate(...)            // NO #[transactional]

#[pallet::call_index(1)]
#[pallet::weight(T::WeightInfo::usdt_staking_delegate())]
#[transactional]
pub fn usdt_staking_delegate(...)       // HAS it
```

`src.matches("#[transactional]").count()` → **1** in the whole pallet. Side-effect order:

```
L3171  T::Currency::transfer(&who, &account_id, need_balance, KeepAlive)?;   // money moves
L3177  DelegatorBalances::mutate(...)
L3180  add_or_update_credit(...)
L3183  delegate_any(who)?                                                    // can Err
```

Verified the transfer really moves funds in the mock (`pool before = 0, after = 1`).
**Not claimed:** that an `Err` at L3183 persists the transfer — that depends on the outer
dispatch wrapping and was not proven attacker-reachable.

## 7. Greps that found candidates

```python
r"([A-Za-z_]\w*)::<T>::(iter|iter_keys|iter_values)\s*\("   # unbounded iteration in a dispatchable
r"\.unwrap\(\)|\.expect\("                                  # panic surface
r"[a-zA-Z0-9_\)\]]\s*[-+*/]\s*[a-zA-Z0-9_\(]"               # raw arithmetic (Substrate panics on overflow)
r"(deposit_creating|mint_into|T::Currency::transfer)\s*\("  # mint/transfer sinks
r"#\[pallet::call_index\((\d+)\)\][\s\S]{0,260}?pub fn (\w+)\("   # extrinsics + indices
```

Then, **for every hit, look upward for the guard** — most die:

- `unwrap()` preceded by `ensure!(x.is_some())`
- `[i - 1]` reachable only when `i > 0`
- `len() - 1` inside `if !is_empty()`
- `balance -= amount` inside `if balance < amount { ...; Err }`
- `rate.unwrap() * reward` where `rate` is a `Perbill` (≤ 100 %, capped at 12 % here)
- `credit_from_burn_nft + credit` bounded by `MaxBurnCreditPerAddress = 50`

For every mint/transfer sink, pair it with its origin check: `ensure_root`,
`has_privilege(...)`, `is_payment_address`, or **nothing**. "Nothing" is the finding.

## 9. Three harness bugs that produced FALSE results

1. **`include_str!` vs CRLF.** `contains("...\n...")` is `false` on a Windows checkout.
   Fix `.replace('\r', "")`; verify with `b"\r\n" in raw`, not by trusting the boolean.
2. **`re.split(r"#\[cfg\(test\)\]")[0]` truncates at the header.** Substrate `lib.rs` declares
   `mod mock; mod tests;` at the top, so `[0]` gave **903 bytes of a 138 KB file** — a fake
   "nothing here" negative I nearly recorded. Split on the last occurrence, or scan whole.
3. **Assuming a mock account holds funds.** Scan for one and assert.

Also: running two test filters (`cargo test d01b d01c`) is invalid — cargo takes one filter.
Use a shared prefix (`d01`) or `--skip`.
