# Substrate: the weight-accounting gap (constant declared reads vs O(N) iteration)

Worked, PoC-verified on DeeperChain @ `ce700b14`, live `specVersion 76` (2026-10-28).
Reported as **Medium**. The discipline lesson is as important as the technique: it was *nearly*
called Critical and the honest bound is what makes it credible.

---

## The bug shape

An extrinsic is charged a **constant** weight but performs **O(N)** storage reads over a map the
attacker can grow.

```rust
// pallets/staking/src/lib.rs L2394-2395
fn delegate_any(delegator: T::AccountId) -> DispatchResult {
    let validators: Vec<_> = Validators::<T>::iter_keys().collect();   // O(N) reads
```

```rust
// storage: no bound
pub type Validators<T: Config> =
    StorageMap<_, Twox64Concat, T::AccountId, ValidatorPrefs, ValueQuery>;
```

```rust
// weights.rs: constant
fn staking_delegate() -> Weight {
    Weight::from_parts(2_656_141_000, 10355)
        .saturating_add(T::DbWeight::get().reads(16_u64))     // <-- fixed 16
        .saturating_add(T::DbWeight::get().writes(9_u64))
}
```

At N = 10,000 the call performs **10,016 reads charged as 16** and takes 700 ms of real execution.

---

## The three-step hunt (≈1 hour per pallet)

### 1. Map iteration reachable from each extrinsic
For every `#[pallet::call]` fn, list every `SomeMap::<T>::iter()/iter_keys()/iter_values()`
reachable — **including through private helpers it calls**. A hit inside a helper still runs inside
the caller's weight budget, and the caller is what gets charged.

### 2. Diff against the generated weights
`pallets/<x>/src/weights.rs` is autogenerated and states the declaration plainly:
`reads(N)` + `writes(M)`. If the code can loop and `N` is a constant, that is the bug.
The header also records the benchmark scenario (`WORST CASE MAP SIZE`, chain, date) — if the
benchmark ran on a `dev` chain with a handful of entries, the measurement never saw the tail.

### 3. Prove the map is attacker-growable
Read the setter's origin check. `ensure_signed` + a low deposit means yes. Compare the deposit to
`ExistentialDeposit` in the runtime:

```rust
// runtime/src/lib.rs
pub const ExistentialDeposit: Balance = DPR / 5;   // 0.2 DPR
// primitives/src/lib.rs
pub const DPR: u128 = 1_000_000_000_000_000_000;
```

### 4. The clincher — find the same pattern capped elsewhere
The single strongest piece of evidence, because it is the authors' own code proving intent:

```rust
// L2921  elect() iterates the same map...
// L2950  validators.truncate(Self::validator_count() as usize);   // ...but caps it
```

`delegate_any()` has no such truncation. Measured in the mock: `validator_count() cap = 2` while
`delegate_any` iterates all 503 entries. Quote both sites in the report.

## Bounding the severity — do this before grading

Three facts decide Medium vs Critical. Answer all three explicitly.

| Question | DeeperChain answer | Consequence |
|---|---|---|
| What does the victim path require? | `verify_atomos_signature(nonce, signature, who)`; `AtmosAccountid` is a **single global `StorageValue`**, message = `blake2_256(atomos_accountid ++ nonce ++ sender)` | Not remotely triggerable by an arbitrary attacker |
| Can one account repeat it? | gate `dst_level > cur_level`, `CreditLevel = Zero..Eight` (9 variants) | max 8 triggers per account — no spam loop |
| Does a scheduled loop already walk N? | `elect()` iterates the same set every era | large validator sets are an accepted cost at rotation |

Verdict: **Medium** (block-space griefing by a party holding a device signature).
A constant-weight-vs-O(N) gap with a device-signature gate is **not** a chain halt. Say so in the
report — the reviewer will otherwise downgrade you and trust you less next time.

## Secondary pattern worth checking: missing `#[transactional]`

`staking_delegate` moves currency, mutates balances, updates credit, and only **then** calls the
fallible `delegate_any()`. Its sibling `usdt_staking_delegate` carries `#[transactional]`; it does
not (1 occurrence in the whole pallet).

```rust
T::Currency::transfer(&who, &Self::account_id(), need_balance, KeepAlive)?;   // money moves
DelegatorBalances::<T>::mutate(&who, |b| *b = b.saturating_add(need_balance));
T::CreditInterface::add_or_update_credit(...);
if dst_level > 0 { Self::delegate_any(who.clone())?; }                        // may Err
```

**Do not claim fund loss from the asymmetry alone.** Whether an `Err` persists the transfer depends
on the outer dispatch wrapping. Report it as an observation with the structural asymmetry proven and
the fund-loss consequence explicitly *not* claimed.

## Pallet PoC harness — four traps that each cost a build cycle

1. **`re.split(r"#\[cfg\(test\)\]")` truncates the file at its header.** `#[cfg(test)] mod tests;`
   appears near the top of `lib.rs`, so splitting on it made a 138 KB file look like 903 bytes and
   produced a **false "no findings" pass**. Slice on the *last* occurrence (`m[-1].start()`), or
   scope the search to `fn` bodies.
2. **CRLF breaks `include_str!` matching.** The checkout is CRLF; a pattern written with `\n` never
   matches. Always `include_str!("lib.rs").replace('\r', "")` before string-matching source.
3. **`ExtBuilder` vs `new_test_ext`.** Pallets differ: `staking` uses `ExtBuilder::default()
   .build_and_execute(|| {...})`, `deeper-node` uses `new_test_ext().execute_with(|| {...})`. Read
   the existing `tests.rs` for the pallet before writing yours.
4. **Do not assume mock accounts hold funds.** Account 11 in one mock held 0, so a transfer measured
   "moved 0". Scan for a funded account first:
   ```rust
   let mut who = 0u64;
   for cand in 1u64..300 { if Balances::free_balance(&cand) > 0 { who = cand; break; } }
   ```
