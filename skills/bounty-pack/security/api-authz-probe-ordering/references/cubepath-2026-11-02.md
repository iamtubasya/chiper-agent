# cubepath.com — hardened-target honest-negative (2026-11-02)

Cloud hosting platform (VPS/baremetal/CDN/DDoS, billing+quota). FastAPI cloud API
(`api.cubepath.com/openapi.json` = 221 paths), React dashboard (`my.cubepath.com` behind Cloudflare
Turnstile), OIDC SSO (`identity.cubepath.com`), MCP server for AI. Scope page:
`cubepath.com/security`.

Result: **no confirmed exploitable vuln** after exhaustive auth/IDOR/mass-assignment/CSRF/CORS/XSS/
SSRF/OAuth/subdomain testing. This is the reference for "the honest negative is the deliverable", and
for the two techniques that almost caused a false negative (below).

## Technique 1 — the X-Requested-With CSRF gate (the false-negative trap)

Every write via curl returned `403 {"detail":"Forbidden"}` — identical shape to a real authz refusal.
The gate was actually the missing `X-Requested-With: XMLHttpRequest` header. Re-sending with the header
changed `403 Forbidden` into the true answer:

| probe (session cookie, no header) | with `X-Requested-With: XMLHttpRequest` |
|---|---|
| `PUT /projects/8691` (other acct's project) | `404 {"detail":"Project not found"}` — redacted authz |
| `DELETE /projects/8691` | `404 Project not found` |
| `POST /account/switch-organization/8735` | `403 You are not a member of this organization` |
| `POST /account/api-tokens` | `400 {"detail":"Account not verified"}` |
| `PUT /projects/8690` (own) | `200 "Project '…' updated successfully"` |

Conclusion re-derived each time: **a bare `403` with no other header is not evidence of authz.** See
§1d for the rules.

## Technique 2 — Turnstile-managed signup automation (Playwright)

`my.cubepath.com/register` is Cloudflare Turnstile, but it is the *managed* (non-interactive) mode:
the token auto-fills the hidden input `input[name='cf-turnstile-response']` within ~2 s in a headed
real-Chrome persistent profile. So signup is fully automatable without solving anything:

```python
from playwright.sync_api import sync_playwright
ctx = p.chromium.launch_persistent_context(PROFILE, headless=False, channel="chrome",
        args=["--disable-blink-features=AutomationControlled"], viewport={"width":1440,"height":900})
page.goto("https://my.cubepath.com/register", wait_until="domcontentloaded")
page.locator("input[type=email]").first.fill(EMAIL)
page.locator("input[type=password]").first.fill(PASSWORD)
page.get_by_role("checkbox").first.check()              # "accept ToS" — get_by_role, not input[type=checkbox]
ti = page.locator("input[name='cf-turnstile-response']")  # poll until len(tok)>10 (managed auto-fill)
page.locator("button[type=submit]").first.click()         # POST identity.cubepath.com/account/signup
```

The signup POST body is `{"email","password","captcha_token":"<turnstile token>"}` to
`identity.cubepath.com/account/signup` → `200 {"detail":"User successfully registered"}`. Email-confirm
token arrives in the welcome email as `my.cubepath.com/verify-email#token=<32hex>`; confirm it with
`POST identity.cubepath.com/account/verify-email {"token":…}` (needs the same X-Requested-With header).

## Two-account IDOR proof via Gmail +alias

Gmail `+` aliases (`RESEARCHER_USERNAME+cubepathTA1@gmail.com`, `…TA2@gmail.com`) both signed up cleanly
(cubepath does NOT canonicalise `+`, unlike Adafruit in §6). Sequential integer IDs confirmed:
account 8580/8581, org 8734/8735, project 8690/8691, ssh_key 1343/1344. Cross-account matrix
(PUT/DELETE/switch-org/ssh_key) all correctly redacted once the header was set.

## Tiered verification gate (the coverage gap shape)

`/account/me` returned TWO flags: `email_verified` (email-confirm link) and `verified`
(account/KYC/payment). `email_verified:true` unlocked SSH-key/certain writes; `verified:false`
returned `400 "Account not verified"` on deploy/API-token/DNS/CDN/object-storage/project-create.
Mass-assigning `verified:true`/`role:admin`/`balance:…`/`active_organization_id` via `PUT
/account/update` was silently whitelist-rejected (Pydantic `extra:ignore`). So the highest-value
surface (VPS/baremetal IDOR, billing/quota logic) was legitimately unreachable without a real
payment method — state it as a coverage gap, not "no findings".

## What was tested (verified negatives, with tool evidence)

- IDOR/BOLA: project, org, ssh_key (two-account cross-tenant) — 404/403 redacted.
- Mass assignment: `PUT /account/update` whitelist.
- CSRF: `X-Requested-With` + strict CORS (only `my.cubepath.com` in ACAO; evil-origin preflight 400).
- Stored XSS: React escapes; project name/desc stored raw but not executed.
- OAuth dynamic registration: RFC 8252 loopback-only; `localhost.evil.com`, `192.168.*`,
  `169.254.169.254` all rejected.
- SSRF webhook (`triggers/notificators`): webhook_url must be HTTPS + gated by `verified`.
- Subdomain takeover: `cdn/mirror` CNAME → own `*.cubecdn.io`; internal subs (gitlab/harbor/
  phpmyadmin.k3s) do not resolve publicly.
- nuclei (full http templates): 0 hits (Cloudflare-fronted, hardened).

Secondary services locked: Sentry (SSO `login/cubepath/`), listmonk (`/api/*` 403), MCP
(permission-scoped OAuth approval flow, no credential leak).
